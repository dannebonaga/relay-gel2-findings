## Verifikasi sumber (anchored)

### Klaim sitasi salah sejak awal
- **`ResolverSandbox.sol` hanya 67 baris** — sitasi ":254-260" tidak mungkin. Sweep ERC-20 sesungguhnya ada di baris **54–60** (`run()` loop `returnTokens`: `balanceOf(sandbox)` penuh → `safeTransfer(recipient)`).
- **`RelayFundingPool.sol:26-28`** menunjuk ke import block, bukan logika pool. Natspec `@dev` line 26–28 justru menyatakan model custody: *"every token in the pool is either credited to an account balance or an unattributed direct transfer. Neither withdrawal path below can reach another account's balance."*
- `Multicall3.sol` 264 baris — versi fork kanonik + satu perbaikan (required-call revert membawa return data asli, bukan error generik).

### K1 — msg.value tertahan (Multicall3)
- Faktual **via `aggregate`/`aggregate3`/`tryAggregate`** (payable, tanpa invariant): surplus msg.value memang tertahan di kontrak. TAPI:
- **`aggregate3Value` (line 153–177) TIDAK BISA menahan surplus**: post-loop `require(msg.value == valueAccumulator)` (line 176-177) memaksa total nilai subcall == msg.value; mismatch → seluruh bundle revert → native kembali ke pemanggil. Klaim "msg.value tertahan bila subcall tidak memakai semua" **hanya berlaku untuk entry-point non-Value**, dan surplus itu **tidak bisa diambil siapa pun**: satu-satunya gerakan native adalah subcall `.call{value:v}` di mana `v` tercatat di `valueAccumulator` dan harus didanai msg.value transaksi itu sendiri — saldo lama tak pernah bisa dialirkan keluar (poC: self-drain dengan value = saldo lama → "Multicall3: value mismatch" revert).
- **Tidak ada `withdraw`/`sweep`/`rescue` di Multicall3** — dan itu justru sifat kanonik deployment infra publik (pemanggil tanggung jawab sendiri; Foundry-deploy standard). Repo hanya menyediakan `DeployMulticall3.s.sol`; **tidak ada kontrak Relay yang memanggil Multicall3 dalam flow settlement** (grep `aggregate3|Multicall` di contracts/ → hanya test + router sendiri). MulticallRouter (yang benar-benar dipakai flow) punya `sweep()` self-call + natspec eksplisit "whatever a bundle leaves behind is takeable by anyone" — kebalikan dari klaim.

### K2 — aggregate3Value subcall-gagal refund tertahan
- `allowFailure=false` gagal → `_revert` → seluruh tx revert → native kembali ke pemanggil (PoC `test_K2_requiredFailureRefundsCaller`: balance Multicall3 == 0, pemanggil utuh).
- `allowFailure=true` gagal **dengan value>0** → call-level revert mengembalikan value ke Multicall3 → **ya, tertahan** (PoC trace: 0.5 ETH tertahan). Bagian ini klaim benar secara mekanisme — tapi identik K1: invariant `msg.value == valueAccumulator` membuatnya **tak bisa ditarik siapa pun** (drain attempt revert). Catatan: ini perilaku identik Multicall3 kanonik di semua chain Ethereum (deployment 0xcA11bde05977b3631167028862bE2a173976CA11 yang dipakai ratusan protokol) — dikenal, diterima trade-off, bukan bug Relay.

### K3 — token tercecer di ResolverSandbox
- `run()` menyapu **penuh** `balanceOf` setiap token di `returnTokens` (bukan delta) — caller flow (`PoolResolverBase._runInSandbox` line 425-442) selalu memasukkan **inToken & outToken** (satu atau dua entri), lalu `_sweepRequestTokens` menyapu sisa di resolver. Residual hanya mungkin bila solver call menghasilkan token di LUAR {in,out} — token itu tetap bisa diambil owner (resolver) pada `run()` berikutnya dengan returnTokens diisi (PoC `test_K3_forgottenTokenRecoverableByOwnerOnly`).
- **Tidak ada exit permissionless**: `msg.sender != OWNER` → `UnauthorizedCaller` (PoC attacker revert). OWNER = resolver trusted yang deploy sandbox (constructor `PoolResolverBase` line 125).
- **Native ETH di sandbox memang tidak disapu `run()`** (PoC `test_K3b_nativeResidualHasNoSweep`) — residual native class ini hidup hanya bila solver call mengirim native ke sandbox; flow funding sandbox hanya ERC-20 (`_fundSandbox`/draw-leg `safeTransfer`), sehingga eksposur praktis nihil.

### K4 — RelayFundingPool unattributed residual
- Exit paths yang ADA: `withdraw(token,amount,recipient)` (WITHDRAWER_ROLE, saldo-gated `balances[msg.sender]`), `withdraw(PoolWithdrawal,sig)` (account-signed, permissionless relay, saldo-gated), `debit` (RESOLVER_ROLE, transfer-out dari saldo account), `credit` (masuk). **Tidak ada sweep/rescue untuk residual unattributed** (direct transfer tanpa `depositFor`).
- PoC `test_K4_unattributedResidualLockedButUnreachable`: direct-transfer 1_000 → withdraw WITHDRAWER atas jumlah itu **gagal** (`InsufficientBalance` — mapping `balances` tak tersentuh); saldo terattributed tetap bisa keluar penuh via signed withdrawal (attacker sebagai relayer sukses); residual 1_000 tertinggal. `test_K4b_debitCannotReachResidual`: `debit` pada account tanpa saldo revert — residual tak pernah ikut keluar.
- **Kunci verdict**: residual terkunci **bagi semua orang** — admin sekalipun tidak punya fungsi ambil (dan pool non-upgradeable: non-proxy, roles dari constructor). "Prekursor theft bila ada jalur ambil" = kondisi yang jalurnya **tidak ada di kode**; mendambahkannya butuh redeploy kontrak baru (residual lama tetap terkunci selamanya). Sebanding dengan stuck-ETH pada kontrak non-sweep umum — kerugian donasi/typo-transfer, bukan attack surface.
