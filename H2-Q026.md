# H2-Q026 — Idempotency source jahat/selfdestruct/upgrade → settlement halt global

**Hipotesis (LA-OR-016):** idempotency source eksternal (legacy oracle) yang jahat / di-selfdestruct / di-upgrade → `RelayOracleIdempotencyStore.isExecuted` revert atau salah → SEMUA eksekusi oracle (mint global) revert → settlement halt tanpa circuit-breaker.

**Jalur kode yang diklaim:** `RelayOracleIdempotencyStore.sol:96-113` (loop sources di `isExecuted`), `:146-152` (probe try/catch di `_addSource`).

## Grounding ulang ke source (clone fresh)

- **Penulis konfigurasi source:** `addSource(address)` — `onlyRole(ADMIN_ROLE)` (`RelayOracleIdempotencyStore.sol:89`). Hanya admin store yang bisa memasang source; sumber disimpan add-only di `sources[MAX_SOURCES=5]`, `sourceCount`, `isSource` mapping. **Tidak ada `removeSource`** — by-design: menghapus source akan membuka kembali replay window key lama (comment eksplisit di `:55-62`).
- **Validasi saat add (`_addSource`, :132-158):** tolak zero-address, tolak `address(this)`, tolak codeless (`source.code.length == 0`), tolak duplikat, tolak > 5, lalu probe `try source.isExecuted(bytes32(0))` → bila revert/gagal, `InvalidSource`. **Probe hanya SATU key (bytes32(0)), sekali, saat add** — source yang revert selektif (key lain) atau yang berubah jahat SETELAH ditambahkan 100% lolos validasi ini. PoC membuktikan hal ini (`RevertingSource` selektif lolos `addSource`).
- **Pemanggil `isExecuted`:** grep seluruh contracts/ → hanya `RelayOracleV2._isExecuted` (`RelayOracleV2.sol:253-257`) yang membaca `IDEMPOTENCY_STORE.isExecuted` (immutable, di-set di constructor :138-145, reject codeless). Semua jalur exec melewati sini:
  - `execute()` :191 — `if (_isExecuted(key)) revert AlreadyExecuted` → `_execute()` → `IDEMPOTENCY_STORE.markExecuted(key)` :413 → `HUB.mint/burn/transfer`.
  - `executeMultiple()` :160-176 — **`_isExecuted` dipanggil DI LUAR try/catch** (:165, hanya `continue` bila true); try/catch hanya membungkus `this.execute(...)`. **Revert dari source BUBBLE-UP dan membatalkan SELURUH tx** — bahkan elemen batch lain yang tidak tersentuh key mana pun ikut gagal. Ini jauh lebih buruk dari `ExecutionFailed` event path (yang hanya untuk revert DALAM execute).
- **`markExecuted` (store, :117-125):** juga memanggil `isExecuted` (sama-sama loop sources) → revert source juga menghentikan penandaan key, tapi ini tercakup jalur exec di atas.
- **Mitigasi yang tersedia admin:** (a) upgrade source **in-place** di address yang sama (source adalah kontrak legacy oracle — di luar kontrol store); (b) TIDAK ADA lepas-source (add-only), TIDAK ADA circuit-breaker/pause di store maupun oracle, TIDAK ADA skip-source. HUB pause tidak ada juga (mint hanya role-gated). `markExecuted` writer = oracle dengan `WRITE_ROLE` — jalur local-write tetap harus melewati `isExecuted` loop.

## Verdict

**Q-026: SURVIVED (CONFIRMED), severity dikoreksi.** Mekanisme klaim terbukti penuh di PoC: satu idempotency source jahat/rusak/selektif-revert membuat seluruh `execute`/`executeMultiple` (mint/burn/transfer/FAST_MINT) gagal — revert bubble-up per-key dan batch-cancel di `executeMultiple` (:165 di luar try/catch), plus varian silent-halt (source jawab true) dan gas-bomb. `addSource` probe hanya `isExecuted(bytes32(0))` sekali saat add — selektif-revert lolos validasi (dibuktikan). Mitigasi terbatas upgrade in-place source; tidak ada removeSource/circuit-breaker.

**BUT — scope likelihood.** Prasyaratnya: (1) admin store menambahkan source yang dikontrol/berubah jahat — source adalah legacy oracle Relay sendiri (trust assumption internal, bukan input publik); ATAU (2) legacy oracle di-hack/di-upgrade rusak (key-compromise/upgrade-bug pihak Relay). Penyerang unprivileged TIDAK BISA memasang source (`addSource` onlyRole ADMIN). Jadi jalur serangannya adalah **second-order**: kompromi/bug pada legacy oracle yang sudah jadi source, atau kesalahan upgrade — bukan trigger langsung dari luar. Severity dampak tinggi (global settlement halt untuk semua mint, termasuk silent variant tanpa revert yang menghentikan batch diam-diam), tapi jalurnya admin-gated → bandingkan dengan aturan bounty: "admin-only S1 no-bounty". Klasifikasi terbaik: **valid shared-fate/dependency risk (S2-info)** — kelemahan desain nyata (missing re-validation source, add-only tanpa escape-hatch, `_isExecuted` di luar try/catch di executeMultiple) yang layak dilaporkan sebagai defense-in-depth, bukan exploitable unprivileged.

**Catatan honesty:** (1) PoC memakai vm.etch untuk mensimulasikan source jahat/selfdestruct — setara dengan hasil kompromi/upgrade source nyata; jalur MENUJUKAN source jahat itu sendiri admin-gated (tidak didemok, dan by-construction tidak bisa oleh pihak luar). (2) Varian silent-halt (source=true) dan gas-bomb tidak ada di klaim asli — temuan tambahan dari falsifikasi, memperkuat shared-fate. (3) `executeMultiple` cancel-batch memperburuk blast radius klaim asli: klaim bilang "semua exec revert", kenyataannya bahkan SATU elemen batch yang tersangkut membatalkan elemen sehat lain dalam tx yang sama.
